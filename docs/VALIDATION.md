## 测试中发现并修复的问题

- **字体变化曾改变原文编号。**给 PDF.js 的每个文字片段额外加空格，会把混合字体的 `AB123` 改成 `AB 123`。现在保留 PDF.js 自带的空格和换行标记；真实 `font-switch.pdf` 回归测试确认编号仍为 `AB123`。复杂 PDF 的阅读顺序仍需人工预览。
- **无文字不能当成成功识别。**图像 PDF 实际提取结果为空；全部选中内容为空时禁止生成空材料。混合文件仍保留真实页码，生成时明确跳过无文字页。
- **密码文件不能一直等待。**遇到密码请求立即销毁读取任务，界面提示在自己的 PDF 软件中先解锁。测试设置 4 秒超时，并确认取消后下一份正常 PDF 仍可解析。
- **完整提示词也要计入预算。**预算包含任务、来源标签、原文和分隔符。测试检查每包不超过所选 Unicode 字符数，同时确认拆分后的原文没有丢失。
- **依赖告警需要处理。**首次审计发现 esbuild 的低等级 Windows 开发服务器告警 [GHSA-g7r4-m6w7-qqqr](https://github.com/advisories/GHSA-g7r4-m6w7-qqqr)。在 Vite 允许的版本范围内更新锁定依赖后再次审计，结果为 0 已知漏洞。

## 当前边界

没有 OCR、模型调用或答案质量评估。PDF 多栏、表格、公式、特殊字体可能提取错误。引用提示不能保证 AI 遵守引用或抵抗文档中的恶意指令。字符预算也不是模型 token 预算。请在把材料交给自己的 AI 服务前核对预览，并在得到回答后核对原文。
